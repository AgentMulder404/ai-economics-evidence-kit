# Contributing

Start with the [four-day plan](docs/FOUR_DAY_PLAN.md). Use its work-package IDs (for example D1-02) in issues and pull requests so dependencies remain visible.

1. Open or claim an issue describing the package, scope, dependencies, and acceptance gate.
2. Keep the change focused on one reviewable outcome.
3. Include synthetic examples and meaningful verification for calculation or governance changes.
4. Update the relevant contract and user instructions when behavior changes.
5. Explain what is implemented, how it was verified, and any remaining limitation in the PR.

Do not commit secrets, private execution payloads, generated databases, or real customer data. Discuss schema changes before changing shared relationships. Preserve unknown values and provenance throughout every transformation.

Contributions are provided under the repository's MIT license. Add attribution and notices required by any third-party code you introduce.
